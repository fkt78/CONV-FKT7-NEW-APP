# Cursor指示書｜【調査のみ】氏名・メールが空の会員データ110件の正体を突き止める

対象リポジトリ: `CONV-FKT7-NEW-APP`（VIP Store PWA）
作成日: 2026-08-25

---

## 0. 背景

`users` コレクション466件のうち、**110件が `fullName` も `email` も未設定**であることが判明した。
バージョン 1.0.256 の修正により、これらは管理画面の顧客リストに `(名前未設定)` として表示されるようになっている。

オーナーの見立ては「ほぼ不要なデータだろう」。**ただし削除の前に、正体を確定させる必要がある。**
万が一クーポンを保有している実在の会員が混ざっていた場合、削除は取り返しがつかない。

### すでに分かっていること

- 登録画面（`src/pages/Register.tsx`）は 氏名・生年月・メール・パスワードを**すべて必須**にしている
- `firestore.rules` の `allow create` も、これらが揃っていないドキュメントの作成を**拒否する**
- したがって「入力せずに登録」は仕組み上できない
- `functions/src/index.ts` には `isRegistrationProfileComplete()` という関数と
  **「未完成・エラー残骸には付けない」** というコメントがあり、
  **中途半端なデータが生まれることは開発時点で想定されていた**（だから110件には会員番号が振られていない）

### 立てている仮説（どれが正しいかを判定してほしい）

| # | 仮説 | 見分け方 |
|---|---|---|
| A | 登録途中で失敗し、取り消し処理（`rollbackRegistration`）にも失敗した残骸 | ほぼ空のドキュメント。`createdAt` が散らばる |
| B | プッシュ通知の登録など `setDoc(..., { merge: true })` が、存在しないドキュメントを作ってしまった | `fcmToken` や `notificationSettings` **だけ**を持つ |
| C | 旧アプリからの移行データで、項目名が違うだけ（＝氏名は別の名前で入っている） | 見慣れない項目名を持つ。`createdAt` が特定時期に集中 |
| D | 上記以外 | — |

## 4. 調べること

### 4-1. 対象の抽出

`users` 全件のうち、**`fullName` が無い / 空文字 / 空白のみ** のものを対象とする（110件の想定）。
実際の件数を報告すること。

### 4-2. 1件ごとに集める情報

| 項目 | 目的 |
|---|---|
| ドキュメントID（uid） | 識別。**報告では先頭6文字だけ**にする |
| **そのドキュメントが持っている項目名の一覧** | **最重要**。仮説B・Cの判定に直結 |
| `createdAt`（あれば） | 発生時期。仮説A/Cの判定 |
| `status` | 値、または未設定 |
| `memberNumber` | 未採番のはず。例外がないか |
| `fcmToken` / `fcmTokenUpdatedAt` の有無 | 仮説B |
| `notificationSettings` の有無 | 仮説B |
| `yellowCards` / `totalSavedAmount` | 実利用の痕跡 |
| `memberGroups` | 食料支援などに登録されていないか |
| **`users/{uid}/coupons` の件数**（使用済み・未使用の内訳） | **削除可否の決め手** |
| **`chats/{uid}/messages` の件数** | **削除可否の決め手**。1件でもあれば実在の人 |

> `coupons` と `messages` の件数取得は、110件ぶんの読み取りが発生します。
> 件数だけでよいので、可能なら集計クエリ（`count()`）を使い、読み取り量を抑えてください。
> 実行時に**総読み取り件数を表示**すること。

### 4-3. 全体の集計（ここが結論に直結）

1. **項目名のヒストグラム** … 「どの項目が何件のドキュメントに存在するか」
   例: `fcmToken: 108件` `createdAt: 12件` `status: 3件` …
   → これで仮説Bか否かがほぼ決まる
2. **持っている項目の組み合わせによる分類** … 同じ項目セットを持つものをまとめ、パターンごとに件数を出す
   例: 「`fcmToken` + `fcmTokenUpdatedAt` のみ = 95件」「`createdAt` のみ = 10件」
3. **`createdAt` の分布**（月ごとの件数）… 特定の時期に集中しているか
   併せて **正常な会員356件の `createdAt` 分布**も出し、**重なりを比較**する
4. **見慣れない項目名**があれば列挙（仮説C＝旧アプリ由来の判定材料）
   `fullName` `email` `birthMonth` `attribute` `status` `createdAt` `memberNumber`
   `yellowCards` `totalSavedAmount` `memberGroups` `fcmToken` `fcmTokenUpdatedAt`
   `notificationSettings` **以外**の項目名は、すべて報告すること
5. **クーポンまたはチャットを持つドキュメントの件数** … 0件なら「全部安全に消せる」根拠になる
