## 2. 実装

### 2-1. `src/components/AffiliateBannerCarousel.tsx`

`CORE_BANNER_SLIDES` の定義の**直前**に定数を追加する。

```ts
/** 常に1番目に固定表示する、最優先バナーの id */
const TOP_BANNER_ID = 'penguin-mobile'
```

次に、`useMemo` 内の並び生成（現在の111行目付近）の **1行**

```ts
    return [FKT_MALL_SLIDE, jobSlide, ...shuffleBannerSlides([...CORE_BANNER_SLIDES])]
```

を、次に置き換える。

```ts
    // ペンギンモバイルを1番目に固定し、FKT Mall・求人がそれに続く
    const topSlide = CORE_BANNER_SLIDES.find((s) => s.id === TOP_BANNER_ID)
    const rest = shuffleBannerSlides(
      CORE_BANNER_SLIDES.filter((s) => s.id !== TOP_BANNER_ID),
    )
    // 最優先バナーが見つからない場合（削除された等）は従来どおりの並びにフォールバック
    if (!topSlide) {
      return [FKT_MALL_SLIDE, jobSlide, ...rest]
    }
    return [topSlide, FKT_MALL_SLIDE, jobSlide, ...rest]
```

#### 注意

- `CORE_BANNER_SLIDES` の**中身（バナー定義）は一切変更しない**。並べ替えもしない
- `FKT_MALL_SLIDE` と `jobSlide` の**定義そのものは変更しない**（順番だけ変わる）
- `shuffleBannerSlides` 関数は変更しない
- `AUTO_PLAY_MS`（5000）などの秒数は変更しない
- カルーセルのロジック（`goTo` / スワイプ / 自動再生 / フェード / ドット）は**一切変更しない**
- **ドットの `key` は `key={s.id}` のままでよい**（同じバナーが2回出ることはないため、重複しない）
- 全7枚のまま。ドットは7個

### 2-2. `index.html` の先読み画像を差し替える

`index.html` に、1番目のバナー画像を先読みする指定がある（16行目付近）。

```html
<!-- LCP候補バナー画像を高優先度で先読み（配列先頭の画像。シャッフル後は変わる場合あり） -->
<link rel="preload" as="image" href="/banners/local-ad-recruit.webp" fetchpriority="high" />
```

**1番目が必ずペンギンモバイルになるため、ここを差し替える。**

```html
<!-- LCP候補バナー画像を高優先度で先読み（1番目に固定表示されるバナー） -->
<link rel="preload" as="image" href="/banners/penguin-mobile.webp" fetchpriority="high" />
```

- コメントも上記のとおり書き換える（「シャッフル後は変わる場合あり」は、固定になったので実態と合わない）
- **他の `preconnect` / `dns-prefetch` / `manifest` の行は触らない**

> これにより、1番目のバナー画像の表示が速くなります。
> 逆にここを直さないと、**表示されない画像を毎回先読みする**無駄が残ります。
