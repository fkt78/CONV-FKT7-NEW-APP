## 0. このタスクのゴール

自社取扱いサービス「ペンギンモバイル」のバナーを、**1周のうち固定で2回**表示させる。

### 変更前 → 変更後

| | 変更前 | 変更後 |
|---|---|---|
| 1周のスライド数 | 7 | **8** |
| ペンギンモバイルの登場回数 | 1回（3〜7番目のどこかにランダム） | **2回（3番目と6番目に固定）** |
| 露出割合 | 1/7（約14%） | **2/8（25%）** |
| 開いてから最初に出るまで | 平均 約25秒 | **必ず10秒後**（その後25秒でもう1回） |

### 変更後の並び（1周8枚）

```
1. FKT Mall            ← 固定（変更なし）
2. 伊賀エリア3店舗 求人  ← 固定（変更なし）
3. ペンギンモバイル      ← 新たに固定
4. 残り4枚をシャッフルした1枚目
5. 残り4枚をシャッフルした2枚目
6. ペンギンモバイル      ← 新たに固定（2回目）
7. 残り4枚をシャッフルした3枚目
8. 残り4枚をシャッフルした4枚目
```

「残り4枚」＝ `local-ad-recruit` / `ka-nabell` / `agoda` / `nexus-card` を毎回シャッフルしたもの。

**変更するファイルは `src/components/AffiliateBannerCarousel.tsx` の1つだけです。**
画像・i18n・バナー定義（`CORE_BANNER_SLIDES` の中身）は **一切さわりません。**

## 1. Step 1: ペンギンモバイルのIDを定数として切り出す

`CORE_BANNER_SLIDES` の定義（`const CORE_BANNER_SLIDES: BannerSlide[] = [` の行）の **直前** に、次を追加する。

```ts
/** 1周のうち固定位置で2回出す、優先表示バナーの id */
const PRIORITY_BANNER_ID = 'penguin-mobile'
```

> ID を直書きせず定数にしておくことで、将来ここだけ書き換えれば別のバナーを優先表示にできる。

---

## 2. Step 2: `useMemo` の並び生成を差し替える

`AffiliateBannerCarousel` コンポーネント内、**111行目付近**の次の1行を探す。

```ts
    return [FKT_MALL_SLIDE, jobSlide, ...shuffleBannerSlides([...CORE_BANNER_SLIDES])]
```

この **1行だけ** を、次の内容に置き換える。

```ts
    // 優先バナー（ペンギンモバイル）を 3番目と6番目に固定し、残りをシャッフルして間に挟む
    const priority = CORE_BANNER_SLIDES.find((s) => s.id === PRIORITY_BANNER_ID)
    const others = shuffleBannerSlides(
      CORE_BANNER_SLIDES.filter((s) => s.id !== PRIORITY_BANNER_ID),
    )
    // 優先バナーが見つからない場合（削除された等）は従来どおりの並びにフォールバック
    if (!priority) {
      return [FKT_MALL_SLIDE, jobSlide, ...others]
    }
    const half = Math.ceil(others.length / 2)
    return [
      FKT_MALL_SLIDE,
      jobSlide,
      priority,
      ...others.slice(0, half),
      priority,
      ...others.slice(half),
    ]
```

### 注意

- `useMemo` の依存配列 `[]` は **そのまま**（アプリを開くたびに1回だけ並びが決まる、という今の挙動を維持する）。
- `FKT_MALL_SLIDE` と `jobSlide` の扱いは **変更しない**。1枚目・2枚目は今までどおり固定。
- `shuffleBannerSlides` 関数自体は **変更しない**。
- `AUTO_PLAY_MS`（5000）などの秒数も **変更しない**。
- `CORE_BANNER_SLIDES` の中身（バナー定義）には **一切触らない**。

---

## 3. Step 3: ドットの key を直す（必須。忘れると壊れます）

同じバナーが1周に2回出るため、**ドットの `key` がバナーIDのままだと React のキーが重複**し、ドットの選択状態が正しく更新されなくなる。

**403行目付近**のドット描画部分を探す。

```tsx
        {slides.map((s, idx) => (
          <button
            key={s.id}
```

`key` の行を次に変える。

```tsx
            key={`${s.id}-${idx}`}
```

- 変えるのは **この1行だけ**。`role` / `aria-selected` / `aria-label` / `onClick` / `style` は **そのまま**。
- `aria-label={`スライド ${idx + 1}`}` は位置ベースなので変更不要。

## 4. 変更してはいけない箇所（念押し）

- `goTo` / スワイプ処理 / 自動再生タイマー / フェード処理
- 画像のプリロード処理（`slides[idx].bgImage` を見ている部分。重複があっても問題なく動く）
- `handleBannerClick` 内の `logBannerClick(s.id, s.labelJa)`
  → 2回出ても同じ `id` で集計されるのが**正しい挙動**。ここは変えない。
- `public/banners/` の画像、`src/locales/{ja,en,vi}/common.json`
