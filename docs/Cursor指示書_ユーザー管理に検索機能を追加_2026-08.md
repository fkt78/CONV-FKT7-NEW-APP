## 0. ゴール

管理画面「ユーザー管理」の一覧に **検索ボックス** を追加する。

**検索対象**: 会員番号 / 氏名 / メールアドレス

## 1. 実装仕様

### 1-1. 検索ボックスの設置

- ユーザー管理のヘッダー行（`ユーザー管理` の見出しとボタン群がある行）の**下に、専用の1行**を追加する
- ヘッダーのボタン群（更新 / 選択したメンバーに送信 / 会員番号を振る / CSV出力）と**同じ行に押し込まない**（横に長くなりすぎるため）
- `<input type="search">` を使う
- プレースホルダ: `会員番号・氏名・メールアドレスで検索`
- `aria-label` を付ける
- 入力があるときだけ「×」（クリア）ボタンを出し、押したら検索語を空にする
- 既存の配色・角丸に合わせる（`border-[#e5e5ea]` / `rounded-lg` / `focus:border-[#0095B6]` など、`AdminDashboard` の全チャット検索欄が参考になる）

### 1-2. 絞り込みの位置

現在の並び:

```ts
const sortedUsers = useMemo(() => sortUsersList(users, sortKey, sortDir), [users, sortKey, sortDir])
```

ここに **絞り込みを1段はさむ**。

```ts
const filteredUsers = useMemo(
  () => filterUsers(sortedUsers, searchQuery),
  [sortedUsers, searchQuery],
)
```

**以降、一覧の描画・件数表示・全選択・CSV出力は `filteredUsers` を基準にする**（例外は 1-6 参照）。

### 1-3. 照合ルール（ここが本体）

検索語が空文字（前後の空白を除いて空）のときは **絞り込まない**（全件を返す）。

検索語を空白で区切り、**すべての語に一致するもの**を残す（AND 検索）。
「稲葉 2002」で「稲葉」かつ「2002」を含む人が出る、という動きにする。

各語について、以下の **いずれかに一致すれば合致**とする。

**(a) 会員番号**

会員番号は `#00421` の形式で表示されているが、次の**すべての入力で引っかかること**。

| 入力 | ヒットすべき |
|---|---|
| `421` | #00421 |
| `00421` | #00421 |
| `#00421` | #00421 |
| `#421` | #00421 |

実装方針: 検索語から `#` と先頭の `0` を取り除いた数字と、`memberNumber` の数値を比較する。
併せて、ゼロ埋め5桁の文字列（`00421`）に対する **部分一致**も許可する。
`memberNumber` が `null`（未採番）の会員は、会員番号では一致しない。

**(b) 氏名**

次のように正規化してから **部分一致**で判定する。

1. 前後の空白を除去
2. 全角スペース・半角スペースを **すべて除去**（「稲葉 愛」でも「稲葉愛」でもヒットする）
3. 全角英数字 → 半角
4. ひらがな → カタカナ に統一（「いなば」で「イナバ」もヒットする）
5. アルファベットは小文字に統一

検索語にも **同じ正規化を適用**すること。

**(c) メールアドレス**

- 小文字にして **部分一致**
- ドットや `+` の除去は **しない**（ここは検索であって同一人物判定ではないため、入力どおりに探せるほうがよい）

### 1-4. 件数の表示

検索ボックスの右（または直下）に、常に現在の状態を出す。

- 検索語が空のとき: `全466名`
- 検索中: `466名中 3名を表示`

数字は `filteredUsers.length` と `users.length` から出す。

### 1-5. 該当なしのとき

一覧の代わりに、次のような案内を出す（テーブルのヘッダー行は残してよい）。

```
「〇〇」に一致する会員が見つかりませんでした
```

「検索をクリア」ボタンを併せて置く。

### 1-6. ⚠️ 既存機能との関係（ここを間違えると事故になります）

現在、以下が `sortedUsers` や `users` を参照している。**それぞれ扱いが違うので、下表のとおりに実装すること。**

| 機能 | 基準にするもの | 理由 |
|---|---|---|
| 一覧の描画 | `filteredUsers` | 当然 |
| 件数表示 | `filteredUsers` と `users` の両方 | 「466名中3名」 |
| ヘッダーの全選択チェックボックス | **`filteredUsers` のうち選択可能な人** | 画面に見えている人だけを選ぶ。見えていない人まで選ばれると誤送信になる |
| CSV出力 | **`filteredUsers`** | 検索した結果をそのまま書き出せるほうが実用的。**ボタンの表示を「CSV出力（表示中◯名）」に変え、何件出るかが押す前に分かるようにすること** |
| 「会員番号を振る」 | **`users`（全件のまま。変更しない）** | 未採番の会員に一括で番号を振る機能であり、検索で絞る対象ではない。**ここを `filteredUsers` に変えないこと** |
| 「選択したメンバーに送信」 | 選択済みの `selectedUids`（現状のまま） | ただし下記の安全策を必ず入れる |

**必ず入れる安全策：検索語を変えたら選択を解除する**

検索条件を変えたときに、**画面に見えていない会員が選択されたまま残る**と、
気づかないうちにその人へクーポンやメッセージが送られる恐れがある。

```ts
// 検索語が変わったら選択をクリアする
useEffect(() => {
  setSelectedUids(new Set())
}, [searchQuery])
```

選択が1件以上ある状態でクリアされた場合は、
`検索条件が変わったため、選択を解除しました` といった短い案内を画面に出すこと（`alert` は使わない）。
