# Cursor指示書｜ブラックリスト自動登録のデプロイとバックフィル

対象リポジトリ: `CONV-FKT7-NEW-APP`（VIP Store PWA）
作成日: 2026-08-25
前提コミット: `beca40c feat(blacklist): ブラックリストの自動登録と正規化照合を追加`（未push）

---

## 0. ⚠️ このデプロイは会員登録の入口を触ります

**`checkBlacklist` が壊れると、誰も新規会員登録できなくなります。**
しかも**エラーは静かに起きる**（お客様が登録できないだけ）ので、こちらからは気づきにくい種類の障害です。

そのため、この指示書は**「本番で登録テストが通るまで、バックフィルに進まない」**という構成になっています。
**第4章のテストは必ず実施してください。飛ばさないこと。**

### 実行順序（この順を守ること）

```
1. push
2. npm run deploy（functions + hosting をまとめて）
3. 本番で新規登録テスト  ← ここが関門。通らなければ第7章でロールバック
4. バックフィル --apply（32件）
5. 本番で「弾かれること」のテスト
6. バージョン採番コミット → push
```

**3 が通るまで 4 に進まないこと。**
バックフィル前なら `blacklist` は実質2件なので、万一の影響が最小で済みます。

## 4. Step 3: 本番での登録テスト（**必須の関門**）

**シークレットウィンドウ**で本番 https://conv-fkt7-new-app.web.app を開く。

### 4-1. 正常な新規登録が通ること（最重要）

架空の名前と、受信できるテスト用メールアドレスで**実際に会員登録してみる**。

- [ ] **登録が完了し、ホーム画面に入れる**
- [ ] エラー（「リクエストが多すぎます」「通信エラー」等）が出ない

**ここが通らなければ、第7章のロールバックに進んでください。バックフィルはしないこと。**

### 4-2. 既存のブラックリスト2件が効くこと

`blacklist` に元から入っているテスト用データ（`ba***@test.com` のもの）と
**同じメールアドレス**で登録を試す。

- [ ] 登録が**拒否される**

### 4-3. 自動登録が動くこと

管理画面で、4-1 で作ったテスト会員に**レッドカード**を出す。

- [ ] Firebase コンソールで `blacklist/{そのuid}` が**新しく作られている**
- [ ] `normalizedFullName` / `normalizedEmail` / `birthMonth` / `active: true` が入っている
- [ ] 続けてイエローカードを取り消して `active` に戻すと、`blacklist` の該当ドキュメントが
      **消えずに `active: false`** になる

### 4-4. 結果を報告する

**4-1 が通ったことを必ず報告してから、第5章に進んでください。**

---

## 5. Step 4: バックフィル（32件）

**第4章の 4-1 が通っていることが前提です。**

```bash
# まず必ず dry-run で件数を再確認
node scripts/backfill-blacklist.mjs

# 件数が「32件前後 / 除外110件前後」であることを確認してから
node scripts/backfill-blacklist.mjs --apply
```

- `--apply` は **1回だけ**実行する
- 実行結果（登録件数 / スキップ件数 / 除外件数）を報告する
- **除外件数が110件前後でなかった場合は中止して報告すること**
  （空の残骸が混ざると、空文字一致で無関係な人を弾く恐れがあります）

---

## 6. Step 5: バックフィル後のテスト

**シークレットウィンドウ**で本番を開く。

- [ ] **正常な新規登録が、まだ通ること**（4-1 とは別の架空の名前・メールで再確認）
- [ ] 停止中の会員と**同じメールアドレス**で登録 → **拒否される**
- [ ] 同じメールに **Gmail のドットや `+`** を足して登録 → **拒否される**
- [ ] 停止中の会員と**同じ氏名・同じ生年月**で登録 → **拒否される**
- [ ] 停止中の会員と**同じ氏名だが生年月が違う**場合 → **登録できる**（同姓同名の別人を弾かないため）

**このうち1つ目が通らなくなった場合は、すぐ報告してください。**

### テスト用アカウントの後始末

4-1 と 6 で作ったテスト会員は、管理画面から**ブラックリストに入れて**残しておくか、
Firebase コンソールで削除してください。**放置しないこと。**
（ブラックリストに入れた場合は `blacklist` にも自動登録されるので、それも併せて削除すること。）

---

## 7. ⚠️ ロールバック手順（4-1 が通らなかった場合）

**バックフィルをしていなければ、functions を1つ前に戻すだけで復旧します。**

```bash
# 直前のコミットの functions に戻してデプロイ
git revert --no-commit beca40c
npm --prefix functions run build
firebase deploy --only functions --project conv-fkt7-new-app
```

- 戻したあと、**再度 4-1 の登録テストで復旧を確認すること**
- 復旧を確認したら、`git revert` の内容をコミットせずに `git checkout .` で作業ツリーを戻し、
  **何が原因だったかを報告すること**（原因が分からないまま再デプロイしない）

## 8. Step 6: バージョン採番コミット

```bash

git push origin main
```

---

## 9. やってはいけないこと

- **4-1 の登録テストを飛ばして、バックフィルに進む**
- **バックフィルの `--apply` を2回以上実行する**
- dry-run の除外件数が想定と大きく違うのに、そのまま `--apply` する
- テスト用アカウントを本番に放置する
- 本番で不具合が出たとき、**その場で修正してデプロイし直す**（**まず報告**）
- `npm run lint` の既存エラーを直す
- `.env` をコミットする / `git push --force` を使う

---

## 10. 完了報告に含めてほしいこと

1. push したコミットのハッシュ
2. デプロイ後の実バージョン番号
3. **4-1（正常な新規登録が通ること）の結果** ← 最重要
4. 4-2 / 4-3 の結果
5. **バックフィルの実行結果**（登録 / スキップ / 除外 の件数）

8. 想定外の警告やエラーがあれば全文
