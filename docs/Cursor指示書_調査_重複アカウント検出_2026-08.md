## 0. 背景とゴール

同じ人がメールアドレスや氏名を変えて **複数の会員アカウントを作っていないか** を確認したい。

携帯の端末番号（IMEI 等）は Web からは取得できないため、**いま Firestore にあるデータだけで照合**する。

### このタスクは「調査」です

**アプリのコードは変更しません。管理画面への機能追加もしません。**
やることは **一度きりの集計スクリプトを書いて実行し、結果を報告する**ことだけです。

結果を見て「疑わしいものがどれくらいあるか」をオーナーが判断してから、
管理画面に組み込むかどうかを別途決めます。**ゼロなら作り込みません。**

### 判定は「疑い」であって「証拠」ではない

出力は **オーナーが人の目で確認するための材料**です。
**自動でブラックリストに入れる処理は絶対に書かないでください。** ステータスの更新も一切行いません。
**このスクリプトは Firestore を読むだけ。書き込みは一切しないこと。**

## 4. 判定ロジック

### 4-1. メールアドレスの正規化

**これが今回の主役です。** Gmail は「ドットを入れる」「+なにかを足す」だけで別アドレスとして登録できるのに、
実際は同じ受信箱に届きます。複数アカウントを作るときの定番の手口なので、ここが最もよく当たります。

```
例: fkt78@gmail.com / fkt.78@gmail.com / fkt78+a@gmail.com → すべて同一
```

**正規化の手順**

1. 前後の空白を除去し、すべて小文字にする
2. `@` で ローカル部 と ドメイン部 に分ける
3. ドメインの読み替え: `googlemail.com` → `gmail.com`
4. **`+` 以降の除去** … 次のドメインのみ対象
   `gmail.com` / `icloud.com` / `me.com` / `mac.com` / `outlook.com` / `outlook.jp` / `hotmail.com` / `hotmail.co.jp` / `live.jp` / `live.com`
5. **ドットの除去** … **`gmail.com` のみ対象**

> ⚠️ **ドット除去を全ドメインに適用してはいけません。**
> `docomo.ne.jp` `ezweb.ne.jp` `au.com` `softbank.ne.jp` `i.softbank.jp` `icloud.com` などは
> **ドットの有無で別人になります。** `taro.suzuki@docomo.ne.jp` と `tarosuzuki@docomo.ne.jp` は別アドレスです。
> ここを間違えると、無関係な人を「同一人物」と誤検知します。

### 4-2. 氏名の正規化

1. 前後の空白を除去
2. 全角スペース・半角スペースを **すべて除去**（「吹田 克己」と「吹田克己」を同一視）
3. 全角英数字 → 半角
4. ひらがな → カタカナ に統一（「すいた」と「スイタ」を同一視）
5. アルファベットは小文字に統一

### 4-3. 疑いの判定と確度

| 確度 | 判定条件 | 備考 |
|---|---|---|
| **高** | 正規化後のメールアドレスが一致 | ほぼ黒。Gmail のドット/+ 変形 |
| **高** | 正規化後の氏名が一致 **かつ** `birthMonth` も一致 | 同姓同名かつ同じ生年月は稀 |
| **中** | 正規化後の氏名が一致（生年月は不一致） | 同姓同名の別人の可能性あり |
| **低** | ローカル部（`@` の前）が完全一致し、ドメインだけ違う | 例: `taro@gmail.com` と `taro@yahoo.co.jp`。参考程度 |

- **確度ごとに分けて出力**すること。全部を同じ扱いにしない
- **1つのグループが複数の条件に当てはまる場合は、最も高い確度で1回だけ出す**（重複して数えない）
- `role === 'admin'` のアカウントは **どの判定からも除外**する
- 2件以上が同じキーになったものだけをグループとして出す（1件だけのものは出さない）

| 列 | 内容 |
